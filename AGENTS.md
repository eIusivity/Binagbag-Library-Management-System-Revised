# Issue Readiness Review

When reviewing a GitHub issue, determine whether it is ready
to move from Planning to Ready.

## Review

Check:

- Goal is clear and explains why the issue exists.
- Requirements describe observable behavior.
- Requirements are unambiguous.
- Important edge cases are considered.
- Done When criteria are objectively testable.
- Scope is sufficiently defined.
- Requirements do not contradict each other.

## Verdict

Return one of:

### READY
The issue contains enough information to begin development.

### REVISE
Explain specifically what is missing, ambiguous, contradictory,
or untestable.

Do not invent missing requirements.
Do not implement the issue.
